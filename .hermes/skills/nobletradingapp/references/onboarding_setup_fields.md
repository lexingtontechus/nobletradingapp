# Onboarding Setup Field Mapping (2026-08-03 — UPDATED)

The Noble Trader Hermes **desktop plugin** (`desktop/plugin.js`) is the sole
onboarding entry point. The wizard collects credentials and POSTs to the agent
backend's `POST /setup`, which writes `.env` + auto-generates
`config/user.local.yaml` + runs DuckDB cold-start.

## Required fields (collected by the plugin wizard → written to `.env`)

| Form field (plugin SETUP_FIELDS) | Env var written | `is_setup_complete()` checks? | Notes |
|---|---|---|---|
| NOBLE_TRADER_PROXY_REDIS_URL | `NOBLE_TRADER_PROXY_REDIS_URL` | ✅ YES | **Full composed Redis URL** with signal user/password embedded: `redis://sub_<32hex>:***@sakura.proxy.rlwy.net:36624`. This is the field the plugin should collect (not separate user/password fields). |
| NOBLE_TRADER_QUOTE_PROXY_URL | `NOBLE_TRADER_QUOTE_PROXY_URL` | ✅ YES | HTTP URL of the proxy SSE endpoint (e.g. `https://noble-trader-proxy-production.up.railway.app`). **No credentials required** — auth is via `X-Plan-Prefix` header derived from the Redis URL. |
| TRADINGVIEW_API_KEY | `TRADINGVIEW_API_KEY` | ✅ YES | TVDA price data API key |
| METAAPI_TOKEN_DEMO | `METAAPI_TOKEN_DEMO` | ✅ YES | Demo (paper) MetaApi token |
| METAAPI_ACCOUNT_ID_DEMO | `METAAPI_ACCOUNT_ID_DEMO` | ✅ YES | Demo account ID |
| METAAPI_TOKEN | `METAAPI_TOKEN` | ✅ YES | Live MetaApi token |
| METAAPI_ACCOUNT_ID | `METAAPI_ACCOUNT_ID` | ✅ YES | Live account ID |
| MT4_MT5_BRIDGE_TOKEN | `MT4_MT5_BRIDGE_TOKEN` | ❌ NO | Deprecated — replaced by `METAAPI_TOKEN` / `METAAPI_TOKEN_DEMO` (2026-08-03). |

## What `is_setup_complete()` actually checks (app.py lines 514-537)

```python
_UPSTREAM_KEYS = (
    "NOBLE_TRADER_PROXY_REDIS_URL",
    "NOBLE_TRADER_QUOTE_PROXY_URL,
)
_TRADEVIEW_KEYS = ("TRADINGVIEW_API_KEY",)
_METAAPI_DEMO_KEYS = ("METAAPI_TOKEN_DEMO", "METAAPI_ACCOUNT_ID_DEMO")
_METAAPI_LIVE_KEYS = ("METAAPI_TOKEN", "METAAPI_ACCOUNT_ID")
```

**RESOLVED (2026-08-03):** The plugin `SETUP_FIELDS` previously collected
`NOBLE_TRADER_SIGNAL_USER`/`PASSWORD`/`REDIS_URL` (split fields), causing
`is_setup_complete()` to return false after wizard submission. Fixed via the
plugin consolidation build — `SETUP_FIELDS` now collects
`NOBLE_TRADER_PROXY_REDIS_URL` (full composed URL) +
`NOBLE_TRADER_QUOTE_PROXY_URL`. The wizard validates the Redis URL via a
TCP-connect check to the host:port extracted from the URL.

## Trading mode + demo→live graduation

- `NT_MODE` env (`demo` / `live`), default `demo`.
- Both MetaApi pairs collected at onboarding → seamless graduation.
- `hermes/portfolio/orchestrator.py` `_check_cold_start_exit()` flips
  `NT_MODE=demo→live` (persists to `.env` + `os.environ`) once cold-start exits:
  ≥ 20 closed trades AND positive realized PnL.
- `resolve_metaapi_credentials(mode)` returns the `*_DEMO` pair for `demo`,
  plain pair for `live`.

| `NOBLE_TRADER_LICENSE_KEY` | Subscription `GITHUB_TOKEN` (entitlement) |

| `GET /setup` (browser wizard) | Native plugin Setup tab (posts to `POST /setup`) |
| `:8080` web dashboard loopback (plugin fallback) | Native shim path only (shells to agent venv) |

## Validation at submit (plugin-side)

- MetaApi pair: `GET https://api.metaapi.cloud/users/<account_id>` with
  `Bearer <token>` → HTTP 200.
- Redis URL: TCP connect to the host:port extracted from the URL → success
  means creds are structurally valid.
- TradingView key: format check (RapidAPI key pattern) — full validation at
  first price fetch.
